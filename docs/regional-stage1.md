## 獲得と表示

独立データ `regional/catalog.json`、純粋ルール `regional-core.js`、UI `regional-ui.js`。既存 `history.json`/戦国データとは別。保存済み訪問を既存WalkedCore.municipalityで自治体/政令区へ正規化し、その地域の全記事を導出する。新規獲得用ストアや施設訪問記録を作らない。v3バックアップは従来の訪問を復元するだけで図鑑も再構成される。獲得時刻を過去の訪問日に偽装しない。未訪問地域/記事は一覧も選択肢も非表示。訪問済みでも公開記事がない地域は空カテゴリ表示。訪問記録を解除するとその地域だけに依存する記事は非表示、共有項目は他の訪問済み対応があれば維持する。

県入口はnative select（iPhoneの標準UIを優先、OSのホイール見た目は実機未確認）。訪問済み地域がある県だけを選択可能。県→自治体→7分類→記事と、7分類→全国の獲得記事の2導線。同じ項目IDを1つだけ表示。記事リストは初回30件、続き30件でDOMを制限。説明・発信主体・出典名/URL/確認日をtextContentと通常リンクで表示、埋め込み・画像なし。

## 差分の作成と適用

外部ツールでローカルへ取得した表の行配列（キーは正確なタブ名）から次のコマンドで限定公開データへ投影する。元表は絶対にGitへ追加しない。exportは今回の列定義に対応するので列定義変更時は先に見直す。両方の公開状態と出典参照/コード/一意性を検証。公開状態の承認は研究担当が行う。この生成器で未承認を昇格させない。

```sh
node scripts/regional-data.cjs export /private/master.json VERSION /private/approved-next.json
node scripts/regional-data.cjs diff regional/catalog.json /private/approved-next.json /private/patch.json
node scripts/regional-data.cjs apply regional/catalog.json /private/patch.json /private/catalog-next.json
```

初回はbase=`empty`。同じ差分の再適用は不変。差分に各レコードのbefore/afterとSHA、基準カタログのSHA、版を保持。対象の更新前が異なる、別のカタログ変更が混ざる、ID衝突、参照切れ、未承認状態、未許可フィールドなら停止。差分適用で全既存データを自動上書きしない。取得不足による削除を防ぐため、未収録レコードは自動削除せず、承認済み削除だけdiff第4引数のJSON `{ "items": ["ID"], "relations": ["ID"], "sources": ["ID"] }` で明示する。関連も削除して参照整合を守る。新版の公開可を再読取し対象指紋を比較してから公開用ファイルと差分だけをPRへ保存する。
