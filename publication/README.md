## 入出力と再実行

```sh
node publication/build.cjs
node --test publication/test.cjs
node tests/area-acquisition.test.cjs
node --test tests/title-backup.test.cjs
```

入力は `releases/20261031-stage1/input.json`、出力は `generated/20261031-stage1/` です。生成器はローカルの5つの既存JSONを、入力に固定した内容ハッシュと照合します。mainのデータが更新された場合は停止し、統合担当が新しい基準版で再審査します。コード・入力・出力を一つのバージョンとして引き渡します。

`delta/` は追加分だけです。空のpeople/sites/historyファイルで本番カタログを置換してはいけません。`lib.cjs` の `applyDelta(base, delta)` は既存レコードを一切消さずに追加し、同じパッケージの再適用では増殖しません。同じ既存IDで内容が違えば拒否します。main配信ファイルへの書込みコマンドは用意していません。

新カードIDは人物ID・歴史記録ID・史跡ID・不変の主張キーから、リンクIDは人物ID・史跡IDから決まります。行番号・名前・生成日時をID材料にしません。承認の指紋には本文・史跡位置・出典等を含め、変更後の承認使い回しを拒否します。既存カードを修正する場合は別途、元IDと獲得履歴を守る移行レビューが必要です。

## 公開審査と担当分担

正本候補は [統合マスター](https://docs.google.com/spreadsheets/d/1tJN3AvRQbCuGLYEd1ann_ge81zosY33no_ps-vf6UWs/edit)。書込み担当は統合Workです。公開担当Workは読み取り専用で、凍結した公開候補版を受け取ります。`公開可` と3実体（歴史・史跡・対応）の状態、9条件、承認指紋が一致したものだけ生成します。人物の略歴完成度を公開条件へ追加しません。

各マスターの新公開状態は「調査中→公開審査待ち→公開可→公開済み」。既存のゲーム収録状態と移行前の公開状態を別列に保存します。`公開済み` は配信後に承認者・コミット・配信日時と照合して統合担当が記録します。生成器は状態を公開済みに更新しません。

公開担当は基準mainが変わっていないか確認し、加算後の全カタログとバックアップ互換テスト、出典・帰属表示、iPhone実機表示を確認してからユーザーへ承認を求めます。本PRの既存アプリ関数による試験はGPS実機・ブラウザ描画・実配信の確認とは別です。

## エリアと人物の成長

`records.json` はcardId / personId / historyRecordId / relationId / siteId / growthAreaId / growthUnitKeyの対応です。growthAreaIdは固定エリア台帳に存在する5桁の市区町村・行政区コードで、growthUnitKeyは `personId|growthAreaId`。将来は獲得済みカードのこのキーをDISTINCT集計します。同じエリアの3枚は3歴史カード・1人物エリア、再訪でも増えません。

町田の町丁目と旧 `n:13209:...` は13209に集約。相模原等の政令市は行政区コードを別々に数えます。政令市全体コード・都道府県・不正コード・町丁目と自治体コードが矛盾するキーは成長エリアへ変換しません。閾値1/3/5/10は仕様として保存し、人物カードの進化処理・UIは実装していません。

## 既訪問エリアに新カードが加わる場合

mainには `reconcileSengokuVisits()` があり、保存済みの市区町村・町丁目・旧全国詳細キーから新しい対象カードを解放できます。今回の実アプリ関数試験では新カードの追加後に過去の20203/旧町丁目記録を与え、再訪なしの解放、再実行時の重複なし、既存・不明カードIDと訪問日時の保全、隣接自治体からの誤解放なしを確認しました。
